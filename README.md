# Kuda: нагрузочное тестирование

Тест-план JMeter, контроллеры нагрузки, конфигурации стенда и мониторинга,
сборщики диагностики и скрипты анализа. Бэкенд хранится отдельно:
https://github.com/Sqaz33/venue-backend, ветка `nt`.

## Состав

- `kuda.jmx` — актуальный сценарий: создание комнаты, три приглашённых участника,
  голосование, выбор победителя и SSE. Все сценарные Groovy-скрипты встроены в JMX.
- `data/catalog.sql` — входные данные каталога: 200 вымышленных тестовых заведений
  с географией, категориями и тегами. Данные пользователей и комнат в дамп не входят.
- `run.ps1` — обычный запуск сценария в Non-GUI, режимы Smoke и Load.
- `stand/start-desktop-capacity.py` — запуск текущего поиска производительности на этом ПК.
- `stand/run_laptop_capacity.py` — общий контроллер для локального и удалённого стенда.
- `stand/capacity_policy.py` — выбор ступеней и уточнение границы производительности.
- `stand/collect_laptop_diagnostics.py` — ожидания PostgreSQL, WAL, I/O и логи контейнеров.
- `stand/results_exporter.py` — результаты JMeter и состояние прогона для Prometheus.
- `stand/finalize_local.py`, `finalize_laptop.py` — сбор результатов и HTML Report.
- `stand/compose*.yaml`, `prometheus*.yml`, `telegraf*.conf`, `dashboard*.json` — настройки стенда и мониторинга.
- Остальные скрипты — развёртывание, диагностика, профилирование, проверки и старые варианты запуска.
- `stand/backups`, `stand/sse-work`, `stand/continuous-check` — сохранённые версии исходников и рабочие Groovy-скрипты.

## Окружение

Использовались Windows, JMeter 5.6.3 с дополнительными Thread Groups, Python,
PowerShell, Docker Desktop и Grafana на порту 3001. Для SSH нужен `paramiko`;
обёртка `remote.ps1` запускает его через `uv`.

Скрипты сохраняют пути исходного стенда: `D:/kuda-load-testing`,
`D:/venue-backend`, `D:/apache-jmeter-5.6.3`. Адреса ПК и ноутбука, порты,
имена контейнеров и пути нужно проверить перед запуском на другой машине.
Python-библиотеки для актуального локального контроллера входят в стандартную поставку.

## Актуальный локальный запуск

Последняя конфигурация в `stand/start-desktop-capacity.py`:

- разгон до 352 комнат/мин за 300 секунд;
- первая ступень — 180 секунд, следующие — по 480 секунд;
- шаг увеличения — 64 комнаты/мин, предельная проба — 1024;
- после устойчивого нарушения выполняется уточнение между прошедшей и не прошедшей ступенью;
- фиксированные ограничения на число потоков участников и SSE отключены;
- предельный бюджет прогона — 7200 секунд;
- ошибки записываются, но исключены из текущего критерия SLA по запросу пользователя;
- снижение нагрузки требует нарушения одной операции в трёх последних последовательных минутных окнах;
  кратковременные нарушения сохраняются отдельно, автоматических повторов ступени нет.

Пример запуска после подготовки стенда и мониторинга:

```powershell
$env:KUDA_GRAFANA_USER = 'admin'
$env:KUDA_GRAFANA_PASSWORD = Read-Host 'Пароль Grafana'
python -X utf8 D:/kuda-load-testing/stand/start-desktop-capacity.py
```

Конфигурация мониторинга: `stand/compose.monitoring.yaml` вместе с
`stand/compose.monitoring.local.yaml`. Конфигурация локального бэкенда:
`D:/venue-backend/compose.yaml` вместе с `stand/compose.desktop.yaml`.
Образ `venue-backend:nt-local` собирался из `Dockerfile.local` бэкенда.
После миграций в отдельной тестовой базе импортируется `data/catalog.sql`.
Это data-only дамп; при повторном импорте нужно заранее подготовить пустые таблицы каталога.

Для настройки Grafana пароль также передаётся через `KUDA_GRAFANA_PASSWORD`.
Он не хранится в репозитории. Локальная обёртка SSH использует зашифрованный
Windows-файл `%LOCALAPPDATA%/kuda-ssh-secret.txt`, который также не входит в Git.
Примеры переменных приведены в `.env.example`; автоматической загрузки `.env` нет.

Windows exporter: версия 0.32.1, файл `windows_exporter.exe` размещается в `stand`.
Ссылка на релиз: https://github.com/prometheus-community/windows_exporter/releases/tag/v0.32.1
Контрольные суммы сохранены в `stand/exporter-checksums.txt`.

## Результаты и остановка

Каждый новый прогон создаёт каталог в `out`. `status.json` с `running=0`
означает окончание нагрузки, `DONE.json` — готовность артефактов.
Файл `stop-requested` внутри каталога текущего прогона запрашивает остановку
новых комнат и завершение уже запущенных.

Результаты, логи, снимки метрик, Docker-образы и загруженные бинарные файлы
исключены через `.gitignore`. Исходники и настройки старых вариантов сохранены;
`README.txt` и `stand/README-local.txt` описывают предыдущие версии.
